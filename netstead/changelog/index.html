Changelog ¶

Summary ¶

This page is the netstead package’s CHANGELOG.md, included verbatim when the site is built, so it always matches the repository. Unreleased changes sit at the top; each release lists what was added, changed, fixed and removed. For what is being built next, see Status and roadmap.

All notable changes to the netstead package. Format follows Keep a Changelog; versioning is Semver.

This file is for the netstead package only. The underlying generic engine corral keeps its own CHANGELOG at packages/corral/CHANGELOG.md.

Unreleased ¶

Added ¶

  • Find answers common requests without calling the model. With a language model selected, the Workbench’s Find tab now reads a request with the offline pattern parser first (“Glenwood Ave between Peace St and Wade Ave”, “I-40 EB”, “all residential links”, “links 5, 6”) and calls the model only when that reading names a street, route number or road type the network doesn’t have, or selects nothing. Such a selection records parsed_by: {"provider": "stub", "mode": "pattern", "grammar_first": true}. Turn it off with select.grammar_first = false. netstead select does the same, and so does Ask: a question the offline assistant reads in full (“select Cedar St between Central Ave and Price Ave and color by lanes”), naming only streets and columns the network has, is planned without the model. The new cookbook page Find links by describing them lists what you can type, when the model is called, and timings. On an OSM Raleigh–Durham network (303k links) with qwen2.5:7b in Ollama, four of eight test requests went from 2.8–6.7 s to under 30 ms.
  • Street names are indexed once per network version (netstead.select.StreetIndex), so resolving a selection no longer re-normalizes every link’s name for each street and anchor. On the Raleigh–Durham network, resolving drops from 230–770 ms to 0.2–4 ms after a 0.16 s build (and from 36 ms to 11 ms for “all residential links”). Names now also match when the request abbreviates a street type or direction (“Hillsborough St” finds Hillsborough Street), leaves out a direction the network has (“Peace Street” finds West and East Peace Street, but “W Six Forks Rd” never finds East Six Forks Road), or misspells it (“Hilsborough Street” and “Glenwod Ave” find the closest name at least 85% alike; names under 5 letters are never guessed). A cross street may also leave out its type, misspelled or not (“Cedar Street from Centrl to Price” finds Central and Price Avenue), but only among the streets that meet the street it crosses: on its own, a word like “parking” is close to some street in any large network. On the Raleigh–Durham network, 481 of 500 cross streets typed without their type and with one typo found the right street, and none of 2,000 dictionary words matched a street. An exact match still wins, and a looser one is noted in the selection’s diagnostics. The Find tab’s cross-street list reads the same index.
  • Faster shortest paths with an S2 cell overlay. GMNSGraph.build_overlay() partitions the routing graph by S2 cells at nested levels (default 13, 11 and 9, about 1, 4 and 16 km across) and replaces each cell’s interior with shortcut edges between the nodes where roads cross its edge, in the style of Customizable Route Planning. GMNSGraph.shortest_path then uses it automatically. Costs are the same as plain Dijkstra (when paths tie, a different one may come back). On an OSM Raleigh–Durham roads network (129k nodes) queries drop from 10.6 ms to 2.0 ms after a 0.8 s build; on the wider Triangle (824k links) from 34 ms to 3.9 ms after 2.2 s. Small networks such as Leavenworth are faster without it. build_overlay(cache=<network path>) keeps the overlay in a _netstead_indexes/ sidecar keyed on the graph’s content and levels, which netstead index drop removes. Node coordinates must be lon/lat, or pass crs= to reproject (needs pyproj). S2 cell ids are computed in numpy (netstead.graph.s2); there is no new dependency.
  • Market Street, San Francisco example network (Overture). netstead.fixtures.market_street ships a 129-node, 186-link roads network around Lotta’s Fountain, built with netstead build --source overture (release 2026-09-23.1) with Overture GERS ids on every link and node, as csv, parquet, zip and datapackage.json. It is listed under Included examples in the Workbench and exercises the Find tab’s Overture GERS id system on real data. Data © OpenStreetMap contributors, ODbL; data from TomTom.

Fixed ¶

  • Local models now see the assistant’s whole prompt. Ollama’s default context window (4,096 tokens on recent versions) cut the Ask prompt to about 2,050 tokens. netstead now asks for 16,384 (new setting llm.ollama.num_ctx) and keeps the model loaded for 30 minutes after each call instead of Ollama’s 5 (new setting llm.ollama.keep_alive). With qwen2.5:7b, “color by speed” and “select Cedar Street and zoom to it” now plan correctly. qwen2.5:7b takes about 0.7 GB more memory (5.0 GB loaded).
  • Ask’s prompt cache is reused on Anthropic. The Workbench’s state (selection, filter, map style) sat inside the cached part of the prompt, so any action rewrote all of it. It is now sent after the cached part. On Haiku 5.5 with Leavenworth, an Ask within five minutes of another costs $0.0002–0.0003 instead of $0.0012.

  • Anthropic’s newest models no longer reject netstead’s requests. Sonnet 5.5 and Opus 5.5 refuse a temperature and a forced tool call, and Haiku 5.5 refuses a temperature; netstead sent both. Catalog models now say which they accept (sampling, forced_tools), and get a low effort so their thinking stays short.

  • “X between A and B” finds segments it used to miss. A street that is partly trunk (a signalized arterial such as Glenwood Avenue) was treated as a freeway, so an at-grade cross street never matched; when no interchange path exists the resolver now tries its at-grade intersections. A street whose own name breaks off (a roundabout with no name, or, on a divided road, the few meters of a cross street spanning the median) left “no path between” its anchors; when the street’s own links don’t connect them, the path may now cross unnamed links and named links up to 20 m long within 3 links of the street, at three times their length so the street is preferred. Service roads, paths and tracks never bridge. The selection’s diagnostics say when either happened. On the Raleigh–Durham network, “Glenwood Avenue between Peace Street and Wade Avenue” and “Hillsborough St between Oberlin Rd and Gorman St” now resolve.

Security ¶

  • netstead app refuses to expose your home folder. A non-loopback host (--host 0.0.0.0, NETSTEAD_APP__HOST or a config file) with an empty io.allowed_roots (which means the home folder) now exits with code 2 and explains how to set the roots. Before, anyone on the network could browse the home folder through the Workbench file browser. Sources named on the command line are still allowed for the session but don’t satisfy the check. Loopback spellings the Host-header guard doesn’t cover (127.0.0.2, LOCALHOST, [::1]) are refused the same way, with their own message. A blank io.allowed_roots entry ([""], which resolved to the current folder) is now a settings error.

Changed ¶

  • Anthropic’s default model is now Haiku 5.5 (claude-haiku-5-5, $0.10 / $0.50 per million input / output tokens, a tenth of Haiku 4.5’s price), and the catalog offers Sonnet 5.5 (claude-sonnet-5-5) in place of Sonnet 5. A select.model you set yourself is unchanged.

  • Workbench Find tab: with the offline parser, Select is a fill-in-the-blanks form. No more guessing the grammar. Pick a pattern (Street; Street between two cross streets; All links of a type; Link ids) and fill its blanks. Street and cross-street fields suggest the open network’s street names, and once a Street is chosen the cross streets narrow to the streets that meet it (new read-only route GET /api/n/{net}/{component}/streets/crossing?name=). The assembled sentence shows under the form and is sent unchanged to the same Select action, so history and replay are the same. Missing blanks block Select and are named. With a language model chosen the free-text box is back, prefilled with the last sentence. The offline parser now also reads all <type> links (and all links) and links 59, 60.

  • Workbench Find tab: the selection fragment is a Segment or a Link list, in the ID system you pick, and you copy it. The Download button is gone: a copy button at the top right of the Fragment box copies it. Segment is the facility’s name (or ref) plus the from/to anchors, re-resolvable on another network version; Link list is only the resolved ids. Neither mixes in the other’s fields, and the utterance is a caption under the box instead of notes in it. A new IDs choice writes GMNS (link_id, node_id), OpenStreetMap (osm_way_id, osm_node_id; ProjectCard osm_link_id, osm_node_id) or Overture GERS (overture_segment_id, overture_connector_id) ids. A system the network has no columns for is disabled with the reason, GERS is refused for ProjectCard (it has no key), and Segment is disabled for a selection with no named facility. Ids that several links share (one OSM way is split into many links) are deduplicated, with a caption. GET /api/selection/export takes form=segment|link_list and id_system=gmns|osm|gers (the older resolved / query still work, in GMNS ids) and returns captions and options (which forms and id systems this selection can use, each null or the reason it cannot). New netstead.select.idsystems; to_fragment and to_projectcard take the segment / link_list forms and an ids= mapping; the GMNS selection schema accepts osm_way_id / overture_segment_id links and osm_node_id / overture_connector_id anchors.
  • Workbench Open / Import: Included examples, and a Back chevron. The wizard’s first screen now ends with Included examples, the networks bundled with netstead (Leavenworth, WA; RDU I-40) with their link and node counts, each opening in one click (GET /api/examples). Bundled examples open even when the install lives outside io.allowed_roots; no other path under the package does. Back is now a chevron at the top-left of the dialog header (hidden on the first screen), and the footer only appears when a step has an action (Next, Estimate, Build, Open).
  • Build network types are now roads and paths. They replace drive / walk / bike / all in the Workbench build form (two checkboxes, at least one), build.network_type (now a list, default ["roads"]), the Build Network action, netstead build --network-type (repeat it or comma-separate) and the Python builders. roads is the drive classes plus busway; paths is bridleway, footway, path, pedestrian, steps, track and cycleway. Proposed, construction, corridor and other non-network highway values are never built, and there is no “all highways” type any more. Overture builds map the same two groups onto Overture road classes. Old names still replay: drive means roads; walk, bike and all mean roads + paths (recorded actions, settings, CLI and API calls; the CLI help marks them deprecated). Unknown names are an error that lists the valid ones.
  • Workbench View tab: swatches beat color-by, collapsible sections, node-first picking, explained overlays. Picking a Links or Nodes color swatch while that layer is colored by a column now turns the column coloring off in the same recorded Style action (the swatch’s tooltip says so). Each View section folds (remembered per browser). A map click or hover only picks layers that are switched on, and a node wins over the link under it. Overlay rows explain themselves with an info tooltip; the Filter section is headed “Show only links where…” with a note that the data is not changed.
  • The Workbench Validate list is grouped by finding type. Instead of 271 near-identical quality.high_speed_residential rows burying everything else, each rule code and severity is one collapsible row (count and the rule’s fix hint once; errors first, then warnings, then info, largest first) that loads its findings, 50 at a time, when opened. The filter menus are labeled Severity, Table and Type, and Type lists the finding types with counts. New route GET /api/n/{net}/{component}/issues/summary returns the groups for the same filters as /issues, built from the whole issue set.
  • The Workbench robot shows its status by color. The header’s language-model icon (and a small dot whose shape says the same) is green when the chosen provider and model are ready, yellow when only the offline pattern parser is in use, and red when the provider is unavailable (missing key, Ollama not running, model not pulled). The tooltip says it in words and keeps the privacy note; the old blue/gray privacy colors are gone.
  • Workbench Validate badge counts what needs attention. The tab’s pill shows the number of errors (red) when there are any, else warnings (amber), else nothing; info findings are never counted. The tooltip still gives the whole breakdown (“Validate — 3 errors, 1 warning, 16 info”), or says “clean” or “not run yet”.
  • Workbench side panel: a View tab, dismissible Edit help, readable badges. The map and style controls (layers, color, width, direction, filter) moved out of the Find tab’s collapsed section into their own View tab right after Find, and the map’s layers button is gone. The Edit tab’s explanatory paragraph hides behind a “x” (and comes back from an info button; remembered per browser). Each tab’s badge is now one pill at the icon’s corner, orange while edits are unsaved, and the tab tooltip says what it counts (“Edit — 2 unsaved edits”, “Find — 16 selected links”, “Validate — 271 warnings, 16 info”).
  • “What is Related?” An info button beside the table Related steps control opens a short explanation with an example, using the real counts for the focused or highlighted records when there are any.

  • The Workbench table’s “Expand a hop” is a “Related: 1 step / 2 steps” control that shows only when Show is Related, with a tooltip explaining how far foreign keys are followed.

  • The Workbench model picker is a header icon. A robot button in the header opens the provider and model picker as a popover (the privacy dot is a badge on it; the tooltip names the provider and model). The picker no longer sits in the Find tab.

  • Workbench: a map button for the View settings, Open as an icon, nodes styled by control type. The map gets a layers button that opens the Find tab’s View section; the header’s Open is an icon button with the same recents menu; and nodes colored by ctrl_type use red (large) signals, orange/amber stop signs, yellow yield and small grey uncontrolled nodes, with a dark outline, signals drawn on top, and a legend that shows each category at its size. The side panel’s dock tabs are icons with tooltips (badges stay as a pill on the icon), so they no longer wrap onto two lines. A natural-language Select or Ask now shows it is working: a spinner in the button and a “Thinking… (provider · model)” line that counts seconds after 3 s.

Fixed ¶

  • Workbench build form: several network types and a visible folder chooser. Network type is now a set of checkboxes (drive, walk, bike, or all highways), and a build keeps a way or segment if any chosen type allows it. BuildNetwork takes network_types: list[str] (a recorded single network_type is still read), and the OSM and Overture builders accept a list of network types. The output-folder step shows the chosen path (or “not chosen yet”), a hint, and a Use button on each folder; Estimate stays disabled until a folder is chosen.

  • Workbench place search shows why it failed. A failed place search (for example, the [osm] extra is missing, or the geocoder is down) now says so in the Area step instead of “No matches.”; the Workbench quickstart installs netstead[server,graph,nl,osm].

  • Categorical cell edits in the Workbench grid are offered the spec’s allowed values, and an out-of-enum value is kept and flagged, never silently lost. Beta testers reported edits to bike_facility, parking and the like “did not persist, with no message”. The server always kept them (with an edit.enum warning); the grid did not show that, and leaving the cell editor with the mouse discarded the typed text without a word. Now a text cell’s editor completes from the spec’s enum plus the column’s existing values (comma-list columns such as allowed_uses complete one token at a time and say “comma-separated”); a cell with an open edit warning is outlined in red with a warning icon and the message as its tooltip; and leaving a cell applies the edit, as in a spreadsheet (Escape discards it).

  • Selection mode filters match GMNS uses. drive now keeps links whose allowed_uses list auto/truck/…; it used to drop every link. An emptied or narrowed selection says why, and the parser sets modes only when you name a travel mode.
  • The Workbench map draws link shapes kept in the geometry table. A network whose links carry a geometry_id into a separate geometry table (the bundled Leavenworth network, for one) drew every link as a straight node-to-node line. viz.buffers.pack_network now takes the optional geometry frame and resolves shapes in GMNS order: an inline link.geometry, else the geometry_id row, else the straight from/to segment.
  • Workbench map: a legible focus color, and direction arrows that follow their offset line. The focused link is now a saturated magenta over a dark casing (it was white: invisible on the light Positron basemap and over white highway casings); highlights keep their cyan and get the same casing. With “Offset directions” on, each link row’s arrow now sits on that row’s own offset line instead of the centerline, so a two-way street shows one arrow per direction rather than two crossed into an X. Arrows sit at the path’s midpoint by length (not its middle vertex), have a dark outline, and grow from 8 px at zoom 13 to 18 px at zoom 18. The selection color is still yours to set (style.colors.selection).
  • A Workbench build’s engine failing to close no longer hides the result. Since corral’s IbisEngine.close() stopped swallowing errors, a failed disconnect in the build job’s finally (or the estimate’s) replaced the build’s real error and its estimate payload, or failed a build whose output was already written. build.close_quietly now logs it as a warning.
  • Quality rules: review follow-ups for #246.
  • quality.high_speed_residential again ignores every character Python’s str.strip() removes around facility_type, including \v, NBSP and other Unicode spaces. The pushdown regex had narrowed this to ASCII whitespace.
  • Whole-number float ids print as ints again: link_id=1, not 1.0. A NaN node_id no longer counts as a node in quality.duplicate_near_nodes.
  • quality.overlapping_links reports each pair once when the geometry table repeats a geometry_id (it uses the first row). Its docs now say it matches shared segments exactly, with no tolerance, and can get slow when many bounding boxes overlap.
  • quality.non_unique_combination:
    • The defaults now include signal_timing_phase (timing_plan_id, signal_phase_num).
    • DEFAULT_UNIQUE_COMBINATIONS is read-only (a MappingProxyType of tuples).
    • A user-configured combination naming a missing table or column is logged as a warning (logger netstead.quality.rules) instead of being skipped silently. It is not an issue, so severity_override=ERROR never turns a missing optional table into a failure. Missing tables in the defaults stay silent.
    • A combinations value of the wrong shape raises a ValueError that shows the expected form.
  • validation.rules settings reject a negative or non-numeric epsilon_units and a malformed combinations when they load, so SetSetting refuses the value up front instead of one bad threshold breaking the whole validation run. The rules keep the same check at run time for configs built in code.
  • quality.duplicate_near_nodes raises ValueError for a negative epsilon_units. It used to skip the check silently.
  • A seeded property test checks the grid self-join against a pairwise scan near large negative and positive origins.
  • The docs index, quickstart and gmns-validate skill list the nine real rules. The skill used to name three codes that don’t exist.
  • The Leavenworth fixture’s datapackage.json is self-contained. Each resource now carries its resolved GMNS 0.97 schema inline instead of a ../../spec/0.97/... path, so the descriptor loads wherever it is copied, including the copy inside leavenworth.csv.zip, which could not resolve any schema before (and still described the package as gmnspy’s). A test fails if an inlined schema drifts from spec/0.97/; scripts/descriptor.py regenerates the descriptor and zip without an OpenStreetMap fetch or the dev-fixtures extra. (#127)
  • The offline report’s “Fix locally” edit log is a schema-valid ProjectCard. netstead.map.edits.dump_edit_log and the browser download (buildYaml in map_component.js) put the facility under links / nodes with ignore_missing: false (the ids were clicked), and move each change’s reason, issue id and edit id from a per-change notes (which the schema forbids) to a netstead.note[<i>]: ... line of the card’s notes, the convention the project-cards plugin reads. Both writers fold control characters and line breaks in a note the same way. load_edit_log / apply_edits read both the new shape and logs written before it, split a note back into reason, issue id and edit id (so a dump → load → dump round trip writes the same file), and yield no edits for a selector that is not ids alone (ids narrowed by another key, or a from / to segment). netstead core still does not depend on projectcard; the tests validate with it when it is installed.
  • Validation and network HTML reports no longer show “API KEY REQUIRED” tiles when zoomed in. CARTO now watermarks its raster basemap without an API key, and a key cannot be added: the report is a static, shareable file, so the key would ship inside it. The default tile_provider is now "esri", the same keyless Esri light-grey canvas the Workbench offers (upscaled past its native zoom 16); "openstreetmap" remains the alternative and "carto-positron" is gone.
  • The netstead CLI starts without the [nl] extra. netstead.select.emit imported jsonschema at module level and the CLI imports the select command group eagerly, so on a netstead[clean,graph] install every command, including netstead doctor and netstead info, died with ModuleNotFoundError: jsonschema. The import is now deferred to validate_fragment, which raises the standard requires the [nl] extra message when called without it.
  • Colab quickstart notebook runs again. Its load cell pointed at a raw GitHub directory URL, which Network.from_source cannot detect a format for; it now fetches the fixture’s zipped-CSV bundle. Its install cell installs the beta from GitHub (nothing is published on PyPI under the new names yet). A contract test now executes the notebook’s code cells.

  • netstead.fixtures.leavenworth.summary() reports the real row counts (121 nodes, 339 links, 429 lanes; the module still said 75 / 214 / 280 from an older 600 m build). A test pins the metadata to the bundled files.

  • netstead.clean geometry ops on networks that keep shapes in the geometry table. simplify_geometry now edits whichever table holds the link shapes (link.geometry inline, else geometry via link.geometry_id; inline wins), so netstead clean simplify-geometry works on the Leavenworth fixture instead of failing with “requires an inline ‘geometry’ column”. The edit and its rollback target that table; check result.edit.table. recompute_lengths resolves each link’s shape through assemble_link_geometry (inline → geometry table → node endpoints) and still writes link.length. A network with shapes in neither place raises a CleanError naming both locations.

Added ¶

  • The Open / Import wizard says up front when an extra is missing. The OpenStreetMap and Overture choices (and place search under Overture) are disabled with an “Install the [osm] extra to use this:” notice, the uv and pip commands with Copy buttons, and a link to the install docs; nothing is installed from the page. A new read-only GET /api/extras reports what imports, sharing its probes with netstead doctor (which now also checks [overture]).

  • Workbench: Find / Inspect / Edit / Cards / Validate panels; the map colored by default. The side panel’s tabs, in order: Find (the utterance box with Select / Ask and the model picker, moved out of the header’s second row, which is gone; the selection’s anchors, diagnostics, export and saved selections; the highlighted links; and a View section with the layer toggles, “Color links by”, a new “Color nodes by”, width, direction / offset / legend and “Filter links”, moved out of the map’s Layers and Map-display popovers, which are gone with their two buttons); Inspect (the focused record’s details); Edit (the edit list, Undo and Redo, the edit warnings, moved here from Issues, and “Save selection as card…”, enabled while the project-cards plugin is loaded); Cards (the plugin’s panel, when loaded); Validate (run / export, the facets and the findings, with repeated structural findings folded into one ▸ code (n) row that expands, and a “Zoom to” crosshair on every located finding); then Assistant. Plugins may register the bare panel id cards only as project_cards (RESERVED_IDS in slots.js). Opening a network colors links by facility_type and nodes by ctrl_type when the tables have those columns (DEFAULT_STYLE; a network without them opens with "none"), the legend shows both, and Style gains node_color_by (validated against the node table, replayed as app.do(Style(node_color_by=...))). GET …/properties and GET …/property/{name} take ?table=node for the node table’s columns.

  • Host API 1.8: plugin tables in the table view. host.register_table(name, title, rows_fn, *, primary_key, columns=None) publishes a read-only table, listed under “Plugins” in the table rail and served by the table routes (/tables, /table/<name>/rows, schema, distinct, locate), so sorting and the column filters (any_of, between, …) work as on a network table. Core builds a pandas frame from rows_fn() and keeps it until the plugin publishes or the network changes; a failing rows_fn is a 500 naming the plugin, and its rail entry says why. Never edited or linked to the map: a row click emits core.table_row ({plugin, table, id}) to the plugin. host.unregister_table(name); a plugin’s tables go when it is unloaded. In the browser, wb.showTable(name) opens the table pane on it. The project cards plugin publishes its catalog as cards_catalog.
  • Host API 1.7: reading inside the sandbox, and a view of history. host.readable(path) resolves a file or folder that exists inside io.allowed_roots (PathNotAllowed outside them, ActionError when nothing is there); host.list_dir(path) lists a folder’s entries ({name, path, kind, is_dir}, folders first, hidden entries skipped), as core’s file browser does; host.history(prefix=None) returns the session’s history entries (the GET /api/history shape) as read-only copies, filtered by Action-type prefix. The project cards plugin uses them for its catalog and session summary.
  • Workbench: Open menu, Save dialog and validity light in the header. The Recent select is gone: “Open…” drops a menu with the three most recent networks (the path is the tooltip; re-opening is a normal open_network) and “Browse / import…” for the wizard. “Save a copy…” is a header button that opens a dialog (name, format, folder, and, when edit warnings are open or the live check failed, the warning text with a “Save anyway” checkbox that is accept_warnings); a save the server refuses reopens the dialog with its reason instead of a browser confirm. The Edits panel keeps only the edit list with Undo and Redo. A validity light before the counts shows not validated / stale / valid / warnings / errors with the counts in its tooltip, and opens the Issues panel.
  • Workbench: Redo, and icon buttons with tooltips. A new redo_edit Action (RedoEdit, replayed as app.do(RedoEdit())) re-applies the edit the last undo_edit took back; the session state’s edits[<net>] gains redo_count, and any other change to the network empties the redo stack. The Edits panel has Undo and Redo icon buttons (a disabled one’s tooltip says why); the header’s Commands, Settings and Jobs controls, the Issues panel’s Run validation and Export report, and the footer’s Session as Python are icon buttons with tooltips (inline SVG from static/js/icons.js); the model picker’s tooltip shows the full model label; the empty “No edit warnings.” text is gone (the count says so).

  • Workbench table filters: token and range operators, distinct values, spec enums. The filter language (the table rows routes and the Filter action) gains any_of, all_of and none_of, which match a list of values against a comma-separated cell such as link.allowed_uses ("auto" matches "auto,truck,walk,bike"), and between, an inclusive [low, high] numeric range. This is the server side of the column-filter popovers; the UI follows.

  • Quality rule quality.overlapping_links (#5). Flags pairs of links whose shapes share a stretch longer than min_overlap_units (default 0, in CRS units), such as a link drawn on top of part of another. Links that meet at a node, cross, or have the identical shape (two-way twins) are not flagged. Reads inline link.geometry or the geometry table via geometry_id; needs shapely ([clean]). One WARNING per pair with extra link_ids, rows and overlap_length. Candidate pairs come from an STRtree box query cut down in numpy before the exact test: 0.2 s on a 100k-link network.
  • Quality rule quality.non_unique_combination (#7). Flags rows that repeat a column combination that should be unique, such as two link_tod rows for the same link_id and time_day (GMNS 0.97 gives the time-of-day tables a surrogate key, so spec validation lets these through). It checks every time-of-day table plus lane / segment_lane lane numbers by default; the combinations threshold replaces that list. One WARNING per repeated combination, with its row positions in extra["rows"]. Grouping runs in DuckDB (0.03 s on a 100k-row link_tod plus a 200k-row lane).

  • Plugin Host API 1.6 (the cards plugin’s follow-ups):

  • Storage refusing an edit (corral’s EditingError, an Arrow, ibis or DuckDB error) while Session.mutate applies it to the draft is an ActionError (“the edit failed: : “), and refusing a reverse in Session.revert is “the undo failed: …”. The message is scrubbed of URL credentials and key-shaped tokens (it reaches history, plugin routes and the assistant); the original is logged. A failure after the edit was applied is not reported as a failed edit. This covers host.mutate, host.undo and core’s edit Actions alike. Breaking for Python callers of Session.mutate, which used to get corral’s exception.
  • Stable edit ids: host.mutate returns a frozen Mutation(results, seq) (exported). Breaking: it used to return the list of EditResults. host.pending_edits(net_id) returns a frozen PendingEdits(issued, edits) (exported), read in one moment: edits are the pending edits’ views (seq, source, note, version, rows, saved) and issued the newest seq handed out. host.undo()’s seq names the edit it reversed. A network id’s seqs are unique for the session: not reused after a rolled-back Action spent one (the ledger used to hand it out again), nor after the network is closed and reopened. The Edits panel’s seqs can have gaps after a rollback.
  • host.on_rollback(fn): a handler registers a callback that core calls when its Action is rolled back, including after it succeeded inside an Action that failed later, so the plugin can put back its own state and files. A callback that raises is logged and the rollback goes on (a BaseException is re-raised once it has finished); host.mutate, derive, undo, dispatch and on_rollback refuse to run from a callback.
  • assistant_compact: ClassVar[bool] = True on a mutates Action offers it in the assistant’s compact tool set (a local model’s), and GET /api/actions entries carry it. Core’s everyday edits (edit_cells, delete_rows, undo_edit) carry the flag, in place of a hard-coded list; what core offers is unchanged.
  • Plugin Host API 1.5: ActionError and NotSupportedYet are exported from netstead.workbench.plugins, so a plugin handler can refuse with a message the user sees (anything else it raises is still an internal error).
  • Workbench plugins (#222, #223). Plugins are pip packages discovered through the netstead.workbench.plugins entry-point group: a WorkbenchPlugin with namespaced Actions (ActionSpec), a router at /api/plugins/<id>, a static front end, settings under [plugins.<id>] and state under plugins.<id>, programmed against a versioned Host (API 1.0 Python core; 1.1 browser slots: activate(wb), workspace tabs, dock panels, commands in the palette and context menus, a map-layer registry and schemaForm). Settings → Plugins lists each plugin with its state and an on/off switch; a plugin that fails to load is isolated, never fatal. Ships the hello example plugin and the netstead.workbench.testing fixture.
  • Cookbook: workbench-plugins.md.
  • Workbench: validate and edit (P2, #225). Run validation as a job with the rule config from Settings; an Issues panel linked to map markers and table rows, Fix on an issue, and Export report. Direct table edits: EditCells (live warnings re-checked against the spec), DeleteRows (with a cascade dry run), AddRows (Python only), UndoEdit, and Save a copy (SaveNetwork, never overwriting the source). Derived networks carry lineage. Plugin Host API 1.2: host.undo, host.edit_warnings, plan_update / plan_delete / plan_add and version-checked host.mutate.
  • Workbench: verify a selection (P3a). A Selection dock panel in every workspace (the selection’s status, anchors, diagnostics, export and saved selections moved out of Details).
  • Pinning: an ambiguous anchor lists its candidate nodes, drawn on the map (Anchor candidates); PinAnchor(role, node_id) pins one (or the resolver’s own choice) and re-resolves. A pin that resolves nothing is refused. Pins are intent fields (from_node / to_node), never offered to the LLM. When an edit takes a pinned node off its facility, the selection keeps its previous links and says so (stale_pins, a Stale pin warning).
  • Saved selections: SaveSelection, UseSelection, DeleteSelection (session state, replayed with the history; at most 50; tied to the network’s source locator).
  • Export (GET /api/selection/export): a resolved selection, current or saved, as a GMNS fragment (schema-checked) or a ProjectCard facility object, in resolved or query form, with warnings.
  • Workbench: Style, Filter, Navigate. Style(width_by=…) sizes links by a numeric column (Map display → Width by); Filter(where=[…]) is a recorded predicate over link fields (no SQL, no regex) that dims the rest of the map and drives the table’s new Filtered scope (Layers → Filter links); Navigate(record={table, id}) flies to one link or node.
  • Plugin Host API 1.3: host.saved_selections(), host.saved_selection(name).
  • Workbench: the natural-language assistant (P3b). An Assistant dock panel in every workspace, plus Ask (Ctrl+Enter / ⌘Enter) in the header box and Ask the assistant… in the palette; Enter still selects. One conversation per session, never written to disk.
  • Tools: the allowed Actions (assistant.actions; plugins opt in with assistant.plugins) as JSON-schema tools, one model call per question. Read-only steps run at once; the first step that changes a network and every step after it form one draft (Approve / Reject / Edit…), re-checked against each network’s version when approved, with each edit pinned to the version the step before left. A read-only Action the assistant runs can’t change a network through host.dispatch, host.mutate or host.undo, nor open one with host.derive.

Changed ¶

  • The quality rule pack filters in DuckDB instead of materializing tables (#181). Each rule now writes its predicate as an ibis expression and fetches only the offending rows, so findings are unchanged (a golden test pins every field on Leavenworth, RDU I-40 and a synthetic edge-case network) but a 100k-link network checks much faster: duplicate_near_nodes drops from 75 s to 0.04 s (an O(n²) Python scan became a grid self-join), and the other table rules are 7–25× faster. sharp_angle_bends still parses geometries with shapely, now vectorised and reading only link_id and geometry. One visible difference: a message quotes a measured value as stored, so a capacity column of whole-number floats shows 1000.0 where it used to show 1000. Ids are the exception: a float link_id / node_id column holding only whole numbers (a CSV id column with a blank cell) still prints link_id=1, in messages and extra, and a NaN id prints None. The “write your own rule” cookbook example now shows the pushdown pattern.
  • CloseNetwork.mutates is True (it throws away unsaved edits). It is never offered to the assistant either.

Fixed ¶

  • Map: the inline JSON payload is escaped so network data cannot close the script block (XSS) (#224).
  • netstead select on an ambiguous selection no longer crashes with SelectError: cannot emit a fragment from status 'ambiguous'. It now prints the status, the provisional link ids, each anchor with the other nodes it could be (candidates), and diagnostics, and exits 3 (1 stays not-found, 2 invalid settings).   • Assistant approval on a derived copy: a draft that touches a derived network (derived_from, such as a plugin’s preview) also checks the copy’s base, while the base is open. Approving is refused as stale once the base moved, so a plugin that applies the change to the base no longer overwrites an edit made there since the draft.
  • netstead clean <op> <src> without --dest no longer destroys the source. Writing the edited network back over its own directory removed the old files before the unedited tables (still read lazily from them) were written, leaving only the edited table behind and a DuckDB “No files found” error. 1.0.0-beta.1 — 2026-06-29 ¶

First public preview of GMNSpy v1.0, published to PyPI as gmnspy==1.0.0b1 (pre-rename, since yanked; names in this section are as shipped). The entire codebase is a rewrite from v0.3.5 — there is no in-place upgrade path; see the migration guide.

This is a beta: API surface is stable enough to build against and most user-facing rough edges have been smoothed, but we expect bug reports + small breaking changes before 1.0.0 GA.

Headline changes vs v0.3.x ¶

  • New architecture. GMNS-specific code now sits on top of a generic Frictionless engine (datagrove (now corral)) shipped as a separate PyPI package. The intent: future spec toolkits (GTFSpy, etc.) reuse the engine.
  • Multi-version GMNS support out of the box. Spec versions 0.95, 0.96, 0.97 ship side-by-side. DEFAULT_SPEC = "0.97". Override per call: gmnspy.read(..., spec_version="0.96").
  • Regional-scale performance. Lazy ibis + DuckDB by default. Predicates push down to SQL. Validation and scope operations stream rather than materializing the whole network.
  • Three usage modes, one core. CLI (gmnspy <command>), notebook (Network._repr_html_), and programmatic (gmnspy.read, gmnspy.validate) all share the same underlying objects.

New features ¶

  • gmnspy.read(source) + gmnspy.validate(source) — the documented I/O front door. Accepts paths / URLs / loaded Networks.
  • Network.from_source() with multi-version spec auto-load.
  • gmnspy validate CLI with --html <path> for interactive single-file reports + --spec for version override.
  • gmnspy quality — data-quality rule pack beyond spec compliance: high-speed-on-residential, disconnected components, lane-count mismatch, sharp-angle bends, implausible v/c, etc. Plugin-extensible via the datagrove.quality.rules entry point.
  • gmnspy.scope — network-aware scope ops: from_nodes, from_node, from_link, from_point, connected_component, from_zone. Chainable. Returns a scoped Network with FK chain pre-filtered.
  • gmnspy.osm + gmnspy build CLI — build a validated GMNS network from OpenStreetMap for a bounding box, place name (city/county), or a lat/lon point + buffer. Hand-rolled Overpass + Nominatim access (no osmnx / osm2gmns dependency); maintained tag-mapping data files; produces a self-describing network with a config table declaring units. Behind the gmnspy[osm] extra (requests, pyyaml).
  • gmnspy.graph + gmnspy[graph] extra — scipy-CSR routing engine: connectivity (weak / strong components), isochrones, shortest paths, multi-source distance buffer, nearest-node snap. Builds from a Network or directly from parquet/duckdb/polars/in-memory sources. This is also the unified backend powering gmnspy.semantics + gmnspy.scope connectivity / network-distance ops (replacing the older igraph-based index).
  • gmnspy[clean] extra — network editing with atomic rollback (simplify_geometry, merge_close_nodes, remove_orphans, recompute_lengths). Every edit returns an EditResult with diff + log entry; sessions stored as sidecar parquet.
  • gmnspy[server] extra — self-hostable FastAPI server (gmnspy server run). Pluggable bearer-token auth. Ships Dockerfile + docker-compose.example.yml.
  • gmnspy[mcp] extra — MCP server (gmnspy mcp serve) exposing read / describe / query / scope / validate / quality_check / edit_session tools to Claude Desktop / Claude Code.
  • gmnspy[notebook] extra — interactive scope-builder ipywidget. (Basic _repr_html_ ships in core.)
  • gmnspy doctor — install diagnostic: Python version, extras installed, vendored specs, fixture loads, env vars.
  • gmnspy bench — read/validate/connectivity timing.
  • Bundled Leavenworth, WA fixture in four storage variants (CSV / parquet / DuckDB / zip-CSV) — see fixtures/leavenworth/README.md for provenance.

AI surface ¶

  • --json on every CLI command for tool-call loops.
  • llms.txt + llms-full.txt + ai/api-index.json auto-generated from docs + docstrings.
  • Five Claude Code Skills in skills/ — datagrove-validate, gmns-author, gmns-validate, gmns-convert, gmns-clean.

Internal architecture ¶

  • Single graph backend. All connectivity + network-aware-scope ops (gmnspy.semantics.connectivity, gmnspy.scope, gmnspy.quality.rules disconnected-components, Network.build_indexes(graph=True)) now run on a shared gmnspy.graph.GMNSGraph (scipy CSR), cached once per network. The earlier gmnspy.indexes.GraphIndex (igraph) wrapper is retired; the igraph dependency is dropped ([clean] no longer pulls it in). SpatialIndex (STRtree) is unaffected.

Quality + process ¶

  • 1285 tests passing; coverage ≥ 85% on each package (gated in CI).
  • Two automated contract tests assert every documented gmnspy.X / datagrove.X symbol AND every documented gmnspy <cmd> --flag actually exists — prevents doc-vs-code drift.
  • Per-package CI matrix (Python 3.11 / 3.12 / 3.13 × Linux / macOS), import-linter contracts, raw-SQL lint, doctest-modules sweep, htmlproofer.

Breaking changes from v0.3.x ¶

Everything. v1.0 is a clean rewrite — no _legacy/ shims, no DeprecationWarning bridges. The migration guide maps the old API surface to the new. The biggest moves:

  • gmnspy.read_gmns_network(path) → gmnspy.read(path) (auto-detects format) or Network.from_source(path).
  • gmnspy.schema.read_schema(path) → gmnspy.load_gmns_spec(version="0.97").
  • All single-file imports under gmnspy.{schema,validation,utils} → moved to datagrove.spec, datagrove.validation, datagrove.utils.markdown.
  • Pandas DataFrames are no longer the lingua franca — operations are lazy ibis expressions; call .to_pandas() / .to_polars() at the boundary.

  • gmnspy.clean lacks split_link_at_node and snap_to_reference (tracked for v1.1).
