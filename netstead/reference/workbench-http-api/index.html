Workbench HTTP API reference ¶

Summary ¶

netstead app serves one Workbench Session as a local web app. The browser front end is only a client of the routes below; anything it does, a script can do with curl or an HTTP library. The route list is generated on every docs build from the FastAPI app’s OpenAPI document (build_app(session).openapi()), so it cannot drift from the code; a running server serves the same document at /openapi.json and interactive docs at /docs.

Every state change goes through one route, POST /api/actions, whose body is one Action (a JSON object discriminated on its type). The Action schemas are on the Workbench Actions page; GET /api/actions returns the JSON schema of every Action the running session accepts, plugin Actions included. Reads are plain GETs and never recorded in the history.

Events (GET /api/events) ¶

The stream is Server-Sent Events (text/event-stream). It opens with a state event carrying the full session snapshot (the same payload as GET /api/state) and then carries every event the session publishes, each frame named by its type:

  • state — a fresh snapshot after any change (open, close, selection, settings, edits).
  • history — one recorded Action, in the shape GET /api/history lists.
  • job — a background job’s snapshot at each stage change (open, build, validate, save and Ollama pulls run as jobs; POST /api/actions answers 202 with the job and the outcome arrives here).
  • llm — provider and key status after a key is set or removed or a model pulled.
  • navigate — a map navigation request raised by a Navigate Action.

A : keepalive comment is sent after 15 seconds of silence so proxies keep the connection open; ?max_events=N closes the stream after N events, for scripts and tests.

Local-bind guards ¶

On the default loopback bind the server answers 400 to any request whose Host header is not localhost, 127.0.0.1 or [::1], and 403 to any state-changing request that names a foreign Origin or arrives Sec-Fetch-Site: cross-site; see Explore in the Workbench for what that means when you expose the app.

Plugin routes ¶

Each installed plugin’s router is mounted under /api/plugins/<id>/ and its static files under /plugins/<id>/. Those routes depend on what is installed, so they are not listed here; GET /api/plugins names the installed plugins and their state.

Routes ¶

Session ¶

The session as a whole: its state, settings, history and the Action bus.

GET /api/state ¶

Responses: 200 Successful Response

GET /api/config ¶

Responses: 200 Successful Response

GET /api/settings ¶

Responses: 200 Successful Response

GET /api/history ¶

Every entry, plus the import lines that head them as a script (“copy session as Python”).

A nested entry (parent_seq set) is written as a comment, since replaying its parent repeats it, so it needs no import.

Responses: 200 Successful Response

GET /api/actions ¶

Every Action this session accepts, with its owner and JSON schema. Read-only; nothing is recorded.

Responses: 200 Successful Response

POST /api/actions ¶

Apply an action. A job action (open/build) answers 202 with its job; the outcome arrives over SSE.

Request body: a JSON object (free-form; see the description).

Responses: 200 Successful Response · 422 Validation Error

GET /api/events ¶

SSE stream: a state snapshot first, then every published event.

max_events closes the stream after that many events (tests and scripted clients).

Parameter In Type Required Default
max_events query integer or null no

Responses: 200 Successful Response · 422 Validation Error

Jobs ¶

Background jobs started by job Actions (open, build, validate, save) and by Ollama pulls.

GET /api/jobs ¶

Every background job this session started, newest first.

Responses: 200 Successful Response

POST /api/jobs/{job_id}/cancel ¶

Request cancellation; it takes effect at the job’s next stage boundary.

Parameter In Type Required Default
job_id path string yes

Responses: 200 Successful Response · 422 Validation Error

POST /api/check-url ¶

Request body: a JSON object (free-form; see the description).

Responses: 200 Successful Response · 422 Validation Error

Responses: 200 Successful Response · 422 Validation Error

Selection ¶

GET /api/selection/export ¶

The current (or the saved name) selection as a fragment or ProjectCard object, with a file name.

form is the Find tab’s segment (facility name + from/to) or link_list (only the ids), written in id_system (gmns, osm or gers); resolved / query are the older forms. options says which forms and id systems this selection can use ({key: reason or null}), and captions notes ids that several links share.

A saved selection is resolved again on its network as it is now when that network is open from the same source (read-only: the current selection is unchanged). warnings says what the file may not show: a pin that has gone stale (the links are the ones selected before an edit), or a saved selection that could not be checked, or was saved on another version.

Parameter In Type Required Default
what query fragment / projectcard no "fragment"
form query segment / link_list / resolved / query no "resolved"
id_system query gmns / osm / gers no "gmns"
name query string or null no

Responses: 200 Successful Response · 422 Validation Error

Responses: 200 Successful Response · 422 Validation Error

POST /api/assistant/drafts/{draft_id}/reject ¶

Discard the pending draft; 409 when it isn’t pending.

Parameter In Type Required Default

POST /api/assistant/clear ¶

Responses: 200 Successful Response

RelatedQuery ¶

What to find related records for: highlighted ids per table, and how many keys away.

RowsQuery ¶

One page of a table: the GET parameters as JSON, plus related records to filter by and/or tint.

related with related_mode="filter" narrows the rows; with "tint" it only marks them. tint marks rows by a second set of sources while related filters (e.g. the selection’s lanes, tinted by what is focused).

Field Type Required Default Description
offset integer no 0
limit integer no 100
sort string or null no
dir asc / desc no "asc"
filter array of object or null no
ids array of integer or string or null no
related RelatedQuery or null no
related_mode tint / filter no "tint"
tint RelatedQuery or null no

Examples ¶

Read the session state, apply a no-argument Action, and watch one event from the stream. The server must be running (netstead app) on its default port.

curl http://127.0.0.1:8850/api/state
curl -X POST http://127.0.0.1:8850/api/actions \
  -H 'Content-Type: application/json' -d '{"type": "clear_selection"}'
curl -N 'http://127.0.0.1:8850/api/events?max_events=1'
