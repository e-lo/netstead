    CLI reference ¶

    Summary ¶

    netstead is the command-line front door to the library: inspect, validate, convert, build, scope, clean and benchmark GMNS networks, and start the HTTP, MCP and Workbench servers. The command tree below is generated from the live typer app (netstead.cli.app) on every docs build, so it cannot drift from the installed version; netstead --help and netstead <command> --help print the same text in the terminal.

    Three conventions apply across the tree:

    • --json. Every data command accepts --json and then writes exactly one JSON document to stdout, so the result pipes into jq or straight into an agent. The index table marks which commands take it.
    • netstead doctor is an install doctor: Python version, optional extras, vendored spec versions, and whether the bundled Leavenworth fixture loads. To diagnose a network, use netstead validate (spec, schema and foreign-key checks) or netstead quality (data-quality rules).
    • Optional extras. Commands that need an extra (server, mcp, clean, osm, reports, …) are always listed in --help. When the extra is missing they exit with code 1 and one line on stderr, netstead.<module> requires the [<extra>] extra: pip install 'netstead[<extra>]', which names the extra to install; netstead doctor shows which extras are present.

    netstead validate ¶

    Validate source against the GMNS spec.

    Runs the four-pass validator (structural / schema / foreign-key / sync-state) with the GMNS spec auto-loaded — so reading a CSV directory without a datapackage.json gets the real per-table schema checks, not the empty “every table is unexpected” output of the generic corral validate.

    Exit code is non-zero iff any ERROR-severity issue is recorded.

    Examples: Validate the bundled Leavenworth fixture as CSVs::

            $ netstead validate path/to/leavenworth/csv

    Write the interactive map+table HTML viewer::

        $ netstead validate path/to/network --html report.html

    Export findings to a spreadsheet::

        $ netstead validate path/to/network --csv f.csv --xlsx f.xlsx

    Usage: netstead validate [OPTIONS] SOURCE

    Arguments

    Argument Type Required Help
    SOURCE path yes Path / URL to a GMNS network (datapackage.json or CSV/Parquet/DuckDB directory).

    Options

    Option Type Default Help
    --spec text Override the default GMNS spec version (e.g. ‘0.96’). Defaults to netstead.DEFAULT_SPEC.
    --json flag Emit JSON on stdout instead of rich panels.
    --all flag List every finding on its own row instead of folding repeated structural findings into one.
    --html path Write the interactive network-on-map HTML viewer to this path. Falls back to a table-only HTML report when the [reports] extra is not installed.
    --csv path Write the flat findings table to this CSV path.
    --xlsx path Write the flat findings table to this XLSX path (requires [reports] extra).
    --yes, -y flag Auto-approve any gated ops (alternative to CORRAL_AUTO_APPROVE=1).

    Machine-readable: --json writes the result to stdout as JSON.

    netstead convert ¶

    Convert a data package from any supported format to another.

    Loads source (any format corral can read) and writes the same logical package to dest in the target format. Output format is taken from --format when supplied, otherwise inferred from the dest extension; an extension-less dest defaults to partitioned parquet (architecture §6.1).

    Usage: netstead convert [OPTIONS] SOURCE DEST

    Arguments

    Argument Type Required Help
    SOURCE path yes Source data package path/URL.
    DEST path yes Destination path.

    Options

    Option Type Default Help
    --format, -f text Output format (csv/parquet/duckdb/zipcsv). Default: infer from dest extension; fall back to parquet.
    --engine text Engine: DuckDB (the only compute engine).
    --json flag Emit JSON on stdout.
    --yes, -y flag Auto-approve gated ops.

    Machine-readable: --json writes the result to stdout as JSON.

    netstead doctor ¶

    Check your netstead install — Python version, extras, vendored specs.

    This is an INSTALL doctor, not a network doctor. To diagnose a
specific GMNS network, use:

  netstead validate <path>    spec / schema / FK / sync-state checks
  netstead quality  <path>    data-quality rules (high speed on residential, etc.)
  netstead info     <path>    table list + row counts

    Exits non-zero on any install failure.

    Usage: netstead doctor [OPTIONS]

    Options

    Option Type Default Help
    --json flag Emit checks as a JSON array.

    Machine-readable: --json writes the result to stdout as JSON.

    netstead bench ¶

    Run read/validate/connectivity benchmarks; print timings.

    Phases timed (each via time.perf_counter):

    • load — Network.from_source.
    • validate — Network.validate (structural/schema only).
    • links_count + nodes_count — trivial materialization sanity.
    • is_connected — full graph index build + component count (skipped silently when the [graph] extra is missing).

    Output is a dict with phases (list of {phase, seconds}) and a total_seconds summary. --json writes the dict to stdout for machine consumption; otherwise rendered via the standard rich panel.

    Usage: netstead bench [OPTIONS] SOURCE

    Arguments

    Argument Type Required Help
    SOURCE path yes Path/URL to a GMNS network.

    Options

    Option Type Default Help
    --engine text Compute engine (DuckDB is the only one; kept for compatibility).
    --json flag Emit JSON on stdout.

    Machine-readable: --json writes the result to stdout as JSON.

    netstead bench-suite ¶

    Run the DuckDB-path benchmark suite (create / selection / viz-pack).

    Sweeps the requested size tiers over the three operation families from the benchmarking-suite scope, capturing wall-time and peak memory, and emits one structured document. DuckDB (via ibis) is the single compute engine; pandas / polars / pyarrow are I/O formats, so there is no engine axis — the suite measures the DuckDB path and the binary store format.

    --format json (default) emits the canonical regression document; csv flattens the results; md renders the advertising table with an environment stamp and the standing honesty caveats. Fixture definitions live in benchmarks/fixtures.toml; the L tier is resolved from the NETSTEAD_BENCH_LARGE / NETSTEAD_BENCH_LARGE_BBOX env vars (never committed).

    Usage: netstead bench-suite [OPTIONS]

    Options

    Option Type Default Help
    --sizes text S,M Size tiers to sweep (comma-separated: S,M,L).
    --operations text network_create,selection,viz_pack Operation families to run (comma-separated).
    --format text json Output format: json | csv | md.
    --output, -o path Write to this file instead of stdout.
    --repeats integer 3 Macro timing repeats (reported as median + min).
    --warm-repeats integer 20 Repeats for the warm selection number.
    --run-osm flag Include live OSM builds (hits Overpass).
    --fixtures path Override path to a fixtures.toml.
    --commit text Git SHA to stamp into the env block.

    Options

    --engine text Compute engine (DuckDB is the only one; kept for compatibility).
    --spec-version text GMNS spec version (default: latest).
    --format text Output format: csv / parquet / duckdb / zip.
    --json flag Emit a JSON summary on stdout.

    netstead select ¶

    Resolve a natural-language selection to GMNS link/node ids.

    Prints the validated selection fragment on success (exit 0). On an ambiguous result it prints the status, the provisional link ids, each anchor with the other nodes it could be, and diagnostics (exit 3); on not-found it prints diagnostics (exit 1).

    With a language model chosen and select.grammar_first on (the default), the offline grammar is tried first and the model is called only when it can’t read the request with names the network has, as in the Workbench.

    Usage: netstead select [OPTIONS] UTTERANCE SOURCE

    Arguments

    Argument Type Required Help
    UTTERANCE text yes e.g. “I-40 EB between Harrison Ave and NC 54”.
    SOURCE text yes Path/URL to a GMNS network.

    Options

    Option Type Default Help
    --provider text Parser: stub | anthropic | openai | gemini | ollama (default: settings).
    --model text Model id (default: settings, else the provider default; see netstead llm status).
    --engine text Compute engine (DuckDB is the only one; kept for compatibility).
    --json flag Emit JSON on stdout.

    Machine-readable: --json writes the result to stdout as JSON.

    netstead server run ¶

    Start the netstead HTTP server with config from --config.

    Reads corral.api.ServerSettings from the config file (or uses defaults — localhost, no packages, auth=bearer with no token, which fails fast on first request).

    The CLI --bind / --port flags override the matching config keys for one-off testing without editing the file.

    Usage: netstead server run [OPTIONS]

    Options

    Option Type Default Help
    --config, -c path Path to server config (YAML/JSON).
    --bind text Override config bind address (default 127.0.0.1).
    --port integer Override config port (default 8000).

    netstead llm pull ¶

    Download MODEL into the configured Ollama server (llm.ollama.base_url), with progress.

    Exit 1 if Ollama can’t be reached or the pull fails; exit 2 for a bad model name or provider setup.

    Usage: netstead llm pull [OPTIONS] MODEL

    Arguments

    Argument Type Required Help
    MODEL text yes An Ollama model, e.g. qwen3:4b

    Options

    Option Type Default Help
    --yes, -y flag Download without asking first.
